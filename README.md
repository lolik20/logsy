# Logsy — сервис мониторинга uptime

Мониторинг доступности сайтов и API для российского рынка. Пользователь
регистрируется, добавляет проекты (домены) и мониторы (URL + HTTP-метод +
периодичность), а фоновый воркер каждую минуту проверяет эндпоинты и шлёт
email-алерты при падении.

## Возможности

- **Лендинг** с описанием и тарифом (300 ₽ за 1 сайт в месяц).
- **Авторизация** через Яндекс ID или по почте (пароль генерируется на бэкенде
  и отправляется письмом).
- **Проекты** → **мониторы**: URL для проверки, метод `GET/POST/PUT/DELETE`,
  периодичность `1m / 1h / 1d`, ожидаемый код ответа.
- **Планировщик** (node-cron) обходит БД каждую минуту и проверяет мониторы,
  которым подошёл срок.
- **Алерты на почту и в Telegram** при переходе монитора в статус DOWN (и при
  восстановлении). Каналы настраиваются в панели на вкладке **«Алерты»**.
  Telegram подключается так: пользователь жмёт кнопку «Открыть бота», бот по
  команде `/start` присылает `chat id`, который пользователь вставляет в
  панели — создаётся контакт с типом `TELEGRAM`.
- **Контроль SSL-сертификата** домена проекта: тумблер в настройках проекта
  включает слежение за сроком действия сертификата. Письмо-предупреждение
  уходит за неделю, за 3 дня, за 1 день и за 1 час до истечения (и когда
  сертификат уже истёк). Каждое из оповещений отправляется один раз.
- **История проверок** и uptime по каждому монитору.

## Стек

Next.js 14 (App Router) · React · TypeScript · Prisma (PostgreSQL) ·
Auth.js (NextAuth v5) · nodemailer · node-cron · Tailwind CSS · zod.

## Быстрый старт

```bash
cp .env.example .env      # укажите DATABASE_URL к вашему PostgreSQL
npm install
npm run db:push           # создаст таблицы в PostgreSQL
npm run dev               # http://localhost:3000
```

`DATABASE_URL` имеет вид
`postgresql://user:password@host:5432/logsy?schema=public`.

Регистрация: на `/register` укажите email. Без настроенного SMTP пароль будет
**выведен в консоль сервера** — скопируйте его и войдите на `/login`.

### Восстановление пароля

Забыли пароль — на `/login` есть ссылка «Забыли пароль?» (страница
`/forgot-password`). Укажите email → на почту придёт ссылка на страницу
`/reset-password?token=…` (действует 1 час), где в **одно поле** задаётся новый
пароль. Токен одноразовый и хранится в таблице `VerificationToken` (по аналогии
с быстрым входом). Без настроенного SMTP ссылка **выводится в консоль сервера**.

### Запуск проверок

Проверки запускаются **автоматически внутри сервера Next.js** через хук
инструментации (`src/instrumentation.ts`). Как только сервер поднят
(`npm run dev` или `npm run build && npm start`), планировщик (node-cron)
каждую минуту обходит активные мониторы, у которых подошёл срок по их интервалу
(`1m/1h/1d`), пишет результаты и отправляет алерты. Отдельную команду запускать
не нужно.

> Важно: инструментация работает в долгоживущем Node-процессе (`next start` на
> своём сервере/VPS). На serverless-хостинге (напр. Vercel) фоновые задачи не
> живут между запросами — там используйте внешний cron на эндпоинт ниже.

Дополнительные способы (не обязательны):

```bash
# отдельный процесс-воркер (альтернатива инструментации)
npm run worker

# внешний cron дёргает эндпоинт
curl -X POST "http://localhost:3000/api/cron/run?token=$CRON_SECRET"
```

## Переменные окружения

См. `.env.example`. Ключевые:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Строка подключения к PostgreSQL |
| `AUTH_SECRET` | Секрет Auth.js (`openssl rand -base64 32`) |
| `AUTH_YANDEX_ID` / `AUTH_YANDEX_SECRET` | Yandex ID OAuth (иначе кнопка скрыта) |
| `ADMIN_EMAILS` | Email-адреса администраторов через запятую (см. ниже) |

### Yandex ID OAuth

1. Создайте приложение на <https://oauth.yandex.ru/>.
2. В поле **Redirect URI** (Callback URL) укажите:

   ```
   ${NEXTAUTH_URL}/api/auth/callback/yandex
   ```

   Локально это `http://localhost:3000/api/auth/callback/yandex`,
   в проде — `https://ваш-домен/api/auth/callback/yandex`.
3. Выдайте права: «Доступ к адресу электронной почты» и «Доступ к логину, имени и фамилии».
4. Скопируйте `ID` и `Client secret` приложения в `AUTH_YANDEX_ID` и `AUTH_YANDEX_SECRET`.

Колбэк-эндпоинт обрабатывается автоматически catch-all роутом
`src/app/api/auth/[...nextauth]/route.ts` — отдельный обработчик не нужен.
| `SMTP_*` | SMTP для писем (иначе письма пишутся в консоль) |
| `CRON_SECRET` | Токен для `POST /api/cron/run` |
| `TELEGRAM_BOT_TOKEN` | Токен бота из @BotFather (иначе Telegram-алерты пишутся в консоль) |
| `TELEGRAM_BOT_USERNAME` | Username бота без `@` — из него строится ссылка `t.me/<username>` для кнопки в панели |
| `TELEGRAM_WEBHOOK_SECRET` | Необязательный секрет для проверки webhook (заголовок `x-telegram-bot-api-secret-token`) |

### Алерты в Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather), получите **токен** и
   **username** — положите их в `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME`.
2. Пропишите webhook (один раз), чтобы бот отдавал пользователю его `chat id`:

   ```bash
   curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook?url=$APP_URL/api/telegram/webhook&secret_token=$TELEGRAM_WEBHOOK_SECRET"
   ```

3. Пользователь на вкладке **«Алерты»** жмёт «Открыть бота», нажимает
   «Запустить» (`/start`) — бот присылает `chat id`. Пользователь вставляет его
   в поле и сохраняет: в БД появляется `Contact` с типом `TELEGRAM` и значением
   `chat id`, и туда начинают приходить алерты о падении мониторов и SSL.

## Роли и админ-панель

У пользователя есть роль (`role` в модели `User`): `USER` (по умолчанию) или
`ADMIN`. Роль хранится в БД, поэтому после обновления схемы выполните
`npm run db:push`, чтобы добавить колонку.

Чтобы назначить администратора, перечислите его email в переменной
`ADMIN_EMAILS` (через запятую) — при первом входе такому пользователю
автоматически проставляется роль `ADMIN`:

```
ADMIN_EMAILS="admin@example.com, ops@example.com"
```

Что получает администратор:

- вкладку **«Пользователи»** в боковом меню — список всех пользователей с
  краткой информацией (email, имя, роль, статус подписки, число проектов и
  мониторов, дата регистрации);
- на вкладке **«Мониторинг»** — проекты всех пользователей (сгруппированы по
  владельцу) с возможностью открыть любой проект и посмотреть каждый монитор.
  Управление (добавление/редактирование/удаление) остаётся только у владельца.

## Переход на PostgreSQL

В `prisma/schema.prisma` смените `provider = "sqlite"` на `"postgresql"`,
укажите `DATABASE_URL`, затем `npm run db:push`.

## Оплата через Т-Кассу (T-Bank эквайринг)

Биллинг (300 ₽/сайт в месяц) подключён к **Т-Кассе** методом `Init`
(<https://developer.tbank.ru/eacq/api/init>). Доступны три периода оплаты:
**1 месяц** (без скидки), **3 месяца** (−10%) и **1 год** (−20%) — см.
`src/lib/pricing.ts`. Оплаченный период **добавляется к текущей дате
окончания** подписки (продление): если подписка ещё активна, месяцы
прибавляются к остатку, иначе отсчёт идёт от даты оплаты.

1. На вкладке «Тарифы» пользователь выбирает число сайтов и жмёт «Перейти к
   оплате» → `POST /api/billing/pay` создаёт платёж и возвращает `PaymentURL`.
2. В запрос кладётся объект **Receipt** (чек по 54-ФЗ): система
   налогообложения **УСН** (`Taxation`) и **email пользователя** (`Email`),
   на который Т-Касса отправит чек.
3. Пользователь оплачивает на странице Т-Кассы. После оплаты Т-Касса шлёт
   нотификацию на `POST /api/billing/tbank/notification` — подпись `Token`
   проверяется, и при статусе `CONFIRMED` подписка активируется/продлевается
   на месяц.

Ключи и подпись (`Token`) считаются по правилам Т-Кассы: SHA-256 от
отсортированных значений простых параметров запроса плюс `Password`
(см. `src/lib/tbank.ts`).

### Переменные окружения Т-Кассы

| Переменная | Назначение |
|---|---|
| `TBANK_TERMINAL_KEY` | Ключ терминала из личного кабинета Т-Кассы |
| `TBANK_PASSWORD` | Пароль терминала (для подписи запросов) |
| `TBANK_TAXATION` | Система налогообложения чека: `usn_income` (по умолчанию), `usn_income_outcome`, `osn`, `envd`, `esn`, `patent` |
| `TBANK_API_URL` | Базовый URL API (по умолчанию `https://securepay.tinkoff.ru/v2`) |
| `APP_URL` | Базовый адрес сайта — из него строятся Success/Fail/Notification URL |

> В личном кабинете Т-Кассы для терминала должен быть указан адрес
> нотификаций `${APP_URL}/api/billing/tbank/notification`.

## Заметки

- Пробный период (14 дней, 1 сайт) создаётся при регистрации и работает
  независимо от оплаты.
