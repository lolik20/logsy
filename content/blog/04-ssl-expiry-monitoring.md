# Как не проспать истечение SSL-сертификата (и почему одного Let's Encrypt мало)

Сценарий, знакомый каждому, кто держит сайты: в понедельник утром открываете сайт
клиента, а браузер вместо страницы показывает красный экран
`NET::ERR_CERT_DATE_INVALID`. Сертификат истёк ночью. Клиент уже написал, посетители
ушли, конверсия за утро — ноль.

Обиднее всего, что это **на 100% предотвратимо**. Дата истечения сертификата
известна заранее — нужно лишь следить за ней и напоминать вовремя. Разберём, где
именно ломается автопродление и как выстроить надёжный контроль.

## «У меня же Let's Encrypt с автопродлением»

Автопродление — это прекрасно, ровно до того дня, когда оно молча ломается. А
ломается оно регулярно:

- **certbot renew падает в cron**, но письмо об ошибке уходит в спам или на почту,
  которую никто не читает;
- **порт 80 закрыли** после «оптимизации» фаервола — HTTP-01 challenge больше не
  проходит;
- **DNS переехал**, а DNS-01 challenge остался на старом провайдере;
- **сертификат стоит не только на сервере** — ещё на CDN, балансировщике,
  почтовике — и там его продлить забыли;
- сертификат **вообще не от Let's Encrypt**, а платный на год от другого УЦ, и
  никакого автопродления у него нет.

Вывод простой: **автопродление и мониторинг истечения — это две разные задачи.**
Автопродление пытается продлить. Мониторинг проверяет факт: сколько дней реально
осталось у сертификата, который сейчас отдаёт сайт по HTTPS. Второе не заменяется
первым — оно его страхует.

## Что именно проверять

Правильная проверка — не «что написано в конфиге certbot», а «что реально видит
браузер посетителя». То есть — установить TLS-соединение с сайтом и посмотреть на
поле `validTo` предъявленного сертификата. Это ловит все случаи выше разом:
и сломанное продление, и забытый сертификат на CDN, и платный сертификат без
автопродления.

По остатку дней выводим статус:

```ts
export function sslStatusFromDays(ok: boolean, daysLeft: number | null): string {
  if (!ok || daysLeft === null) return "ERROR";
  if (daysLeft < 0)  return "EXPIRED";   // уже истёк
  if (daysLeft <= 7) return "EXPIRING";  // истекает на этой неделе
  return "VALID";
}
```

## Пороги предупреждений — в часах, а не в днях

Для SSL уведомлять «за неделю» мало. Let's Encrypt-сертификаты живут всего 90 дней
и истекают в разы чаще доменов, а последние сутки — самые критичные. Поэтому пороги
имеет смысл задавать **в часах**: за неделю, за 3 дня, за день и за час до
истечения — плюс отдельное «истёк».

```ts
// Пороги в часах по убыванию срочности: неделя, 3 дня, день, час.
const ALERT_THRESHOLDS_H = [7 * 24, 3 * 24, 24, 1];

function currentAlertLevel(hoursLeft: number): number | null {
  if (hoursLeft <= 0) return 0;                // 0 = «истёк»
  let level: number | null = null;
  for (const t of ALERT_THRESHOLDS_H) {
    if (hoursLeft <= t && (level === null || t < level)) level = t;
  }
  return level;                                // null = больше недели, молчим
}
```

## Проверять чаще по мере приближения срока

Раз в сутки проверять сертификат нормально, пока до истечения далеко. Но чтобы
поймать порог «за час», за сутки до конца надо проверять почти непрерывно. Делаем
интервал зависимым от остатка:

```ts
function checkIntervalMs(daysLeft: number | null): number {
  if (daysLeft == null) return 6 * HOUR_MS;   // ещё не знаем
  if (daysLeft > 7)     return 12 * HOUR_MS;  // спокойно — дважды в сутки
  if (daysLeft > 1)     return HOUR_MS;       // последняя неделя — раз в час
  return 10 * 60 * 1000;                      // меньше суток — каждые 10 минут
}
```

## Предупредить один раз на каждом пороге

Проверка идёт каждые 10 минут в последние сутки — но нельзя же слать письмо каждые
10 минут. Нужно уведомить **ровно один раз** на каждом достигнутом пороге.

Приём: в БД храним `sslAlertHours` — самый срочный порог, о котором уже
уведомили. Письмо уходит, только если достигнут порог более срочный, чем
записанный. А если сертификат продлили и до истечения снова больше недели —
сбрасываем поле, чтобы в следующий раз пороги отработали заново.

```ts
const hoursLeft = (info.validTo.getTime() - Date.now()) / HOUR_MS;
const level = currentAlertLevel(hoursLeft);

if (level === null) {
  nextAlertHours = null;                       // продлили — сбрасываем историю
} else if (project.sslAlertHours === null || level < project.sslAlertHours) {
  await notifyProjectSsl(project, level, info); // достигнут более срочный порог
  nextAlertHours = level;
}
```

Ровно тот же паттерн применим к сроку регистрации домена — только пороги там в днях
(месяц, 2 недели, неделя, 3 дня, день), потому что домены продлеваются раз в год.

## Куда слать

Email — обязателен, но его проспать легче всего. Поэтому дублируйте в Telegram:
там сообщение точно увидят. В Logsy предупреждение уходит на **все контакты**
владельца проекта — и на подтверждённые email, и в Telegram — с указанием домена,
издателя сертификата и точного времени истечения.

## Чек-лист «не проспать сертификат»

1. Не полагайтесь только на автопродление — оно ломается молча.
2. Проверяйте **реальный** сертификат, который сайт отдаёт по HTTPS, а не конфиг.
3. Задайте пороги в часах: неделя / 3 дня / день / час.
4. Учащайте проверки по мере приближения срока.
5. Уведомляйте один раз на каждом пороге, сбрасывая историю после продления.
6. Дублируйте алерты в Telegram.
