# SEO: целевая аудитория и карта страниц

Материалы под расширение сайта Logsy: сегменты ЦА, выведенные из функционала сервиса,
и карта из **177 страниц**, в каждую из которых прошиты запросы с реальной частотностью
Яндекс.Wordstat (регион «Россия», широкое соответствие).

## Файлы

| Файл | Что внутри |
| --- | --- |
| `pagemap.tsv` | Карта страниц: URL, H1, сегмент ЦА, тип, частота (целевая и общая), ядро запросов, хвост, комментарий |
| `pagemap.json` | То же в JSON — для генерации отчётов и импорта в таблицы |
| `wordstat-keywords.tsv` | Очищенный пул: 5 560 запросов с частотностью, отсортированы по убыванию |
| `scripts/` | Скрипты сбора и разбора + сырые ответы Wordstat (`wordstat1..4.json`) |

## Как собирались данные

1. **Функционал** разобран по `README.md` и коду (`src/lib`, `src/app`): мониторы и планировщик,
   SSL-контроль, контроль срока домена по RDAP, логирование фронтенд-ошибок, rrweb-записи сессий,
   виджет обращений, канбан задач с перепиской, тест скорости, обход сайта (`siteScanner`),
   cookie-баннер, публичное API.
2. **Частотности** сняты через Яндекс.Директ API v4 Live (`CreateNewWordstatReport` →
   `GetWordstatReport`), регион `225` (Россия). Токен берётся из `.env` (`YANDEX_OUATH`).
   4 прохода, 220 базовых фраз, 7 844 расширения «искали вместе».
3. **Чистка**: отброшены потребительские и омонимичные интенты (провайдеры и скорость интернета,
   госпорталы, игровые серверы, автомобильные коды ошибок, банки, мониторинг в образовании).
   Осталось 5 560 релевантных запросов.
4. **Прошивка**: каждый запрос закреплён ровно за одной страницей — сначала точное ядро,
   затем хвост по правилам. Узкие страницы забирают фразы раньше широких, поэтому
   каннибализации между страницами в карте нет.

Колонка **«целевая частота»** — сумма без размытых запросов. Размытые (помечены `размытый`) —
это широкие или навигационные фразы вроде `проверить сайт` (411 111), `карта сайта` (193 952),
`яндекс метрика` (106 085): частота реальная, но большинство людей ищет другое. Планировать
трафик нужно по целевой частоте, размытые — побочный трафик.

## Повторный сбор

```bash
cd seo/scripts
node ws.mjs seeds1.json wordstat1.json   # сбор частотностей (создаёт отчёты в Wordstat)
node pool.mjs                            # чистка пула → pool.tsv / pool.json
node pages.mjs                           # прошивка запросов → pagemap.tsv / pagemap.json
node build-artifact.mjs                  # HTML-отчёт seo-map.html
```

Скрипты читают `YANDEX_OUATH` из `../../.env`. В `ws.mjs` отключена проверка TLS-сертификатов
(`NODE_TLS_REJECT_UNAUTHORIZED=0`) — это обходной путь для локальной машины, где системный
CA-набор не пропускает `api.direct.yandex.ru`. На сервере строку стоит убрать.

Лимиты API: 10 фраз на отчёт, до 4 отчётов в очереди одновременно (в скрипте — волнами),
очередь чистится перед запуском.

## Оговорки

- Частоты сняты **без операторов** `"` и `!` — это сумма всех уточнений фразы. Перед вёрсткой
  title и H1 ядро стоит перепроверить в кавычках: порядок величины сохранится, абсолют упадёт.
- **60 страниц** в карте имеют нулевую частотность (`/for-saas`, `/help/hacked`, `/sdk/react`
  и подобные). Они оставлены осознанно — под перелинковку, ответы на возражения и посадку
  из рассылок, но планировать по ним трафик нельзя.
- Прямой коммерческий спрос на мониторинг в РФ тонкий (`мониторинг доступности сайта` — 166).
  Основной объём вынесен в аварийные страницы (`/errors/*`, `/help/*`) и бесплатные
  инструменты (`/tools/*`): человек приходит с «ошибка 502», получает разбор и проверку,
  а мониторинг предлагается как способ не повторять.
- Пять страниц карты требуют доработки продукта: публичная статус-страница, тепловая карта
  из записей, публичный отчёт скана, экспорт SLA-отчётов, проверки из нескольких точек.
